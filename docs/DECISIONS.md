# Fairway Mingle Prototype Decisions

## Product-owner decisions — 2026-08-24

- Use local stylized artwork for fictional profiles and courses. The generated SVGs establish final local paths and can be replaced with refined art later.
- Host the built app at the root of a dedicated subdomain.
- Skip onboarding in the canonical demo. Keep the prefilled onboarding concept reachable from Profile.
- Use `Saturday, September 12` as the River Bend proposal date.
- Keep Sofia and Taylor as seeded matches only. Jamie and Drew are discovery-only profiles, preserving a 10-profile deck.
- Discovery filters are display-only.
- `See who likes you` is a real local-fixture screen and is available at every membership level for the stakeholder demo.
- Do not add application authentication. Apache access control is an optional deployment concern.
- Match rows display first names only.
- Unmatching hides the match but preserves its conversation and confirmed outings.

## Technical decisions

- Pin Node 22.14 through `.nvmrc`; current package versions require Node 22.13 or newer.
- Use one persisted Zustand store. Store reset returns the scenario route; navigation remains in React hooks/components rather than in the store.
- Use deterministic canonical IDs such as `match-maya-demo` and `proposal-match-maya-demo` to prevent duplicate demo entities.
- Use `public/demo/**` SVG assets generated by `scripts/generate-demo-assets.mjs`. No remote image or font request is required.
- The first checkpoint includes the foundation, shell, fixtures, state transitions, and a clickable concept slice. Gesture dragging, complete onboarding, dialogs, PWA setup, and Playwright coverage are intentionally deferred to the next increment.
